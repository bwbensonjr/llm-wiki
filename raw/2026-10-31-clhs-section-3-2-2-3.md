## 3.2.2.3 Semantic Constraints

All [_conforming programs_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_c.htm#conforming_program) must obey the following constraints, which are designed to minimize the observable differences between compiled and interpreted programs:

*    Definitions of any referenced [_macros_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_m.htm#macro) must be present in the [_compilation environment_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_c.htm#compilation_environment). Any [_form_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_f.htm#form) that is a [_list_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_l.htm#list) beginning with a [_symbol_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_s.htm#symbol) that does not name a [_special operator_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_s.htm#special_operator) or a [_macro_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_m.htm#macro) defined in the [_compilation environment_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_c.htm#compilation_environment) is treated by the compiler as a function call. 
*   [**Special**](https://www.lispworks.com/documentation/HyperSpec/Body/d_specia.htm#special) proclamations for [_dynamic variables_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_d.htm#dynamic_variable) must be made in the [_compilation environment_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_c.htm#compilation_environment). Any [_binding_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_b.htm#binding) for which there is no [**special**](https://www.lispworks.com/documentation/HyperSpec/Body/d_specia.htm#special) declaration or proclamation in the [_compilation environment_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_c.htm#compilation_environment) is treated by the compiler as a [_lexical binding_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_l.htm#lexical_binding). 
*    The definition of a function that is defined and declared [**inline**](https://www.lispworks.com/documentation/HyperSpec/Body/d_inline.htm#inline) in the [_compilation environment_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_c.htm#compilation_environment) must be the same at run time. 
*    Within a [_function_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_f.htm#function) named F, the compiler may (but is not required to) assume that an apparent recursive call to a [_function_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_f.htm#function) named F refers to the same definition of F, unless that function has been declared [**notinline**](https://www.lispworks.com/documentation/HyperSpec/Body/d_inline.htm#notinline). The consequences of redefining such a recursively defined [_function_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_f.htm#function) F while it is executing are undefined. 
*    A call within a file to a named function that is defined in the same file refers to that function, unless that function has been declared [**notinline**](https://www.lispworks.com/documentation/HyperSpec/Body/d_inline.htm#notinline). The consequences are unspecified if functions are redefined individually at run time or multiply defined in the same file. 
*    The argument syntax and number of return values for all functions whose [**ftype**](https://www.lispworks.com/documentation/HyperSpec/Body/d_ftype.htm#ftype) is declared at compile time must remain the same at run time. 
*   [_Constant variables_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_c.htm#constant_variable) defined in the [_compilation environment_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_c.htm#compilation_environment) must have a [_similar_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_s.htm#similar) value at run time. A reference to a [_constant variable_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_c.htm#constant_variable) in [_source code_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_s.htm#source_code) is equivalent to a reference to a [_literal_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_l.htm#literal)[_object_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_o.htm#object) that is the [_value_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_v.htm#value) of the [_constant variable_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_c.htm#constant_variable). 
*    Type definitions made with [**deftype**](https://www.lispworks.com/documentation/HyperSpec/Body/m_deftp.htm#deftype) or [**defstruct**](https://www.lispworks.com/documentation/HyperSpec/Body/m_defstr.htm#defstruct) in the [_compilation environment_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_c.htm#compilation_environment) must retain the same definition at run time. Classes defined by [**defclass**](https://www.lispworks.com/documentation/HyperSpec/Body/m_defcla.htm#defclass) in the [_compilation environment_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_c.htm#compilation_environment) must be defined at run time to have the same [_superclasses_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_s.htm#superclass) and same [_metaclass_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_m.htm#metaclass). 
This implies that [_subtype_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_s.htm#subtype)/[_supertype_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_s.htm#supertype) relationships of [_type specifiers_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_t.htm#type_specifier) must not change between [_compile time_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_c.htm#compile_time) and [_run time_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_r.htm#run_time).

*    Type declarations present in the compilation [_environment_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_e.htm#environment) must accurately describe the corresponding values at run time; otherwise, the consequences are undefined. It is permissible for an unknown [_type_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_t.htm#type) to appear in a declaration at compile time, though a warning might be signaled in such a case. 
*    Except in the situations explicitly listed above, a [_function_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_f.htm#function) defined in the [_evaluation environment_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_e.htm#evaluation_environment) is permitted to have a different definition or a different [_signature_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_s.htm#signature) at run time, and the run-time definition prevails. 

[_Conforming programs_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_c.htm#conforming_program) should not be written using any additional assumptions about consistency between the run-time [_environment_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_e.htm#environment) and the startup, evaluation, and compilation [_environments_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_e.htm#environment).

Except where noted, when a compile-time and a run-time definition are different, one of the following occurs at run time:

*    an error of [_type_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_t.htm#type)[**error**](https://www.lispworks.com/documentation/HyperSpec/Body/e_error.htm#error) is signaled 
*    the compile-time definition prevails 
*    the run-time definition prevails 

If the [_compiler_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_c.htm#compiler) processes a [_function form_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_f.htm#function_form) whose [_operator_](https://www.lispworks.com/documentation/HyperSpec/Body/26_glo_o.htm#operator) is not defined at compile time, no error is signaled at compile time.
